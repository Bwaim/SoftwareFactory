# Dock App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS app "CAPTN Dashboard" that the user pins in the Dock. It starts the factory server and shows the dashboard in its own window, with the editor in native tabs and a quit warning that stops the server.

**Architecture:** A shared Python helper (`appbuild.py`) builds small Swift app bundles with `swiftc`, from the code of the notifier. The notifier and the new Dock app both use it and a new icon. The Dock app (`dockapp/main.swift`) runs `factory dashboard` through `uv` to get the URL, shows it in a WKWebView, pings the server from Swift, and runs `factory server waiting --json` and `factory server stop` on quit. `factory dashboard` opens the URL in the Dock app when it is installed. The dashboard and editor pages tell the app when the server cannot be reached.

**Tech Stack:** Python 3 (stdlib + pyyaml), pytest, Swift (AppKit, WebKit), plain HTML/JS, POSIX sh.

**Spec:** `specs/2026-11-20-dock-app-design.md`. Read it first. Each task names the spec sections it implements.

### Task 7: The Swift app (spec "The app", "Getting the URL", "Server stopped", "Quit", "Editor in a tab")

**Files:**
- Modify: `software-factory/lib/factory/dockapp/main.swift` (replace the placeholder)
- Test: `software-factory/tests/test_dockapp.py` (compile test), `verification/2026-11-20-dock-app.md` (new manual test list)

**Interfaces:**
- Consumes: `Info.plist` keys `CAPTNUv`, `CAPTNFactory` (Task 4). `factory dashboard` output line `Dashboard: <url>` (Task 5). `factory server waiting --json` (Task 3). `factory server stop`. `/api/ping` with header `X-Factory-Token`. Page messages on handler `captn` (Task 6).

Behavior (one file, plain AppKit, no storyboard):

- [ ] **Step 1: Runner.** A function that runs `<CAPTNUv> run --script <CAPTNFactory> <args>` with `Process`, cwd `NSHomeDirectory()`, environment of the app plus `FACTORY_DOCK_APP=1`, on a background queue. It returns exit code, stdout and stderr.

- [ ] **Step 2: Base URL.** The app keeps `base: URL?`, the last dashboard URL it loaded. It comes from `factory dashboard` (at launch and on `Start` / `Try again`) or from an open URL event. A helper `rebase(url) -> URL` replaces host port and the `token` query item of `url` with those of `base`, and keeps the other query items.

- [ ] **Step 3: Launch and open URL events.** In `applicationWillFinishLaunching`, register a `kInternetEventClass` / `kAEGetURL` handler with `NSAppleEventManager`. When a URL arrives, set `base`, load it in the dashboard window (create the window if it does not exist), and activate the app. In `applicationDidFinishLaunching`, if no URL arrived, show `Starting the factory…` and run `dashboard`. On exit 0, take the URL from the `Dashboard: ` line. On failure, show the output and `Try again`.

- [ ] **Step 4: Windows.** Each window has a WKWebView with a shared `WKProcessPool` and the `captn` message handler. `tabbingMode = .preferred`. The window title follows the page title. `WKUIDelegate.createWebViewWith` returns a web view in a new window (a tab of the current one), built from the given configuration. Navigation to a host other than `127.0.0.1` opens in `NSWorkspace.shared.open` and is cancelled. Menu: app menu with Quit (Cmd+Q), Edit menu (copy, paste, select all, undo, redo, so text fields work), View menu with Reload (Cmd+R) and the standard tab items. Reload loads `rebase(current URL)` and never runs `factory dashboard`.

- [ ] **Step 5: Server checks.** A 60-second timer sends `GET <base>/api/ping` with `X-Factory-Token`. On a `"unreachable"` message, or a failed timer ping, the app sends one more ping to confirm. If it also fails, the dashboard window shows `Server stopped` and `Start` over the web view. `Start` runs `dashboard`, sets `base`, loads the URL in the dashboard window, and hides the screen. Editor windows are not reloaded. The app never runs `dashboard` without a click.

- [ ] **Step 6: Quit.** `applicationShouldTerminateAfterLastWindowClosed` returns true. The warning runs in `windowShouldClose` of the last window and in `applicationShouldTerminate`, once per quit, with a `confirmed` flag set by the first. Rules:
  - The quit reason is logout, restart or power off (`kAEQuitReason` of the current Apple event): no alert, stop the server, quit.
  - The ping fails: no alert, quit.
  - Run `server waiting --json`. Not empty: the alert with `Stop`, `Keep server running`, `Cancel` always shows. Empty: if `UserDefaults` key `skipQuitWarning` is true, stop and quit without alert; else the alert with `Quit`, `Cancel` and the suppression checkbox titled `Don't show again`. Save `skipQuitWarning` only when the box is checked and the user clicks `Quit`.
  - Stop means `server stop`, run before the app exits (wait at most 10 seconds). `Keep server running` quits without it. `Cancel` keeps the window open.
  - A click on the Dock icon with no dashboard window (`applicationShouldHandleReopen`) creates the dashboard window and loads `base`, or runs `dashboard` when `base` is nil.

- [ ] **Step 7: Compile test.** In `test_dockapp.py`, `test_swift_source_compiles`: when `xcrun --find swiftc` works, run `swiftc -typecheck lib/factory/dockapp/main.swift`. Expected: exit 0.
