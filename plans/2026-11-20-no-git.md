# Workspaces Without Git Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A folder outside git (and a machine without the `git` program) can be a factory workspace. Every pipeline declares `worktree: true | false`, and folder pipelines run in the workspace root.

**Architecture:** `repo.py` gets git probes that never fail on a missing `git` program, and a workspace-root lookup by `.factory/factory.yaml`. `Ctx.git` tells if a workspace is in git. The registry, the pipeline check, launch, session, Herdr adapter, delete and the dashboard branch on `pipeline.worktree` and `task["worktree"] is None`. Data version 3 adds `worktree: true` to existing pipelines.

**Tech Stack:** Python 3 (stdlib + pyyaml), pytest, plain HTML/JS.

**Spec:** `specs/2026-11-20-no-git-design.md`. Read it first. Each task names the spec sections it implements.

## Global Constraints

- All code changes stay in `software-factory/`, except this plan and the spec. Work on branch `git_and_worktree`.
- No code comments. No docstrings. Match the style of the surrounding code (short functions).
- Commit messages: short, plain. Never add a `Co-Authored-By` line.
- Run tests from `software-factory/` with `uv run --with pytest --with pyyaml pytest -q <paths>`.
- Tasks 1 to 8: run only the test files or test functions that the task adds or changes. Do not run the full suite. Task 9 runs the full suite once.
- Exact texts (copy them as written):
  - `GIT_MISSING`: ``The `git` program is not installed.``
  - `NEEDS_GIT`: ``This workspace is not in a git repository. The pipeline `{id}` needs a worktree. Set `worktree: false`, or use a git workspace.``
  - Plain init check: ``This folder is not in a git repository. Only pipelines with `worktree: false` can run.``
  - No task: `Cannot find the task for this folder. Add --task <id> to the command.` (existing text in `repo.current_task_id`)
  - Check, missing key: ``The pipeline has no `worktree` key. Set `worktree: true` or `worktree: false`.``
  - Check, wrong type: ```worktree` must be `true` or `false`.``
  - Check, folder with create-worktree: ```create-worktree` cannot be in a pipeline with `worktree: false`.``
  - Check, folder with branch input: ``A pipeline with `worktree: false` cannot have a `branch` input.``
  - Check warning, git step: ``The step `{sid}` is a git step, and the pipeline has `worktree: false`.``
  - Missing worktree folder: `The worktree {path} of task {id} does not exist.`

## Review Focus

1. A plain workspace nested inside a git repository (for example `~/repo/notes/` with its own `.factory/`). Expected: git wins, as in D3. The workspace root is the git main repository. Pinned by `test_git_wins_over_factory_folder` in Task 1.
2. A folder-pipeline task in a git workspace whose Herdr workspace is open. Closing the task must close only its tab, never the user's Herdr workspace. Pinned by `test_folder_task_closes_only_tab` in Task 5.
3. A v2 pipeline file without a trailing newline, or with comments. The migration must keep the file text and add one line. Pinned by `test_migration_keeps_text` in Task 3.
4. A task launched before the migration (v2, worktree path set) and resumed after it. Expected: no change. Pinned by `test_worktree_task_resume_unchanged` in Task 4.
5. A pipeline whose git step sits inside a group step. The warning must still show. Pinned by `test_git_step_in_group_warns` in Task 2.
